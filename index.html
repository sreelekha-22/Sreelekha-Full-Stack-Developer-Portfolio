Vykronis — Autonomous Incident Response

Flagship

A closed-loop, human-gated incident-response platform. Detects production anomalies, investigates root cause with a tool-constrained AI agent (with deterministic rule-based fallback), gates every action through a fail-closed policy engine, and remediates only after explicit human approval.

  • 9 Spring Boot microservices across a 14-module Maven build, wired together as one Docker Compose stack
  • Event-driven core — 6 Kafka topics with versioned JSON-Schema contracts (metrics, traces, JFR, alerts, deployments, remediation)
  • Kafka Streams correlation engine — 60s windowed detection with a GlobalKTable deployment join and ranked severity
  • 9-state incident state machine persisted in PostgreSQL via Flyway; every transition auditable
  • Tool-constrained AI agent — hypotheses are never fabricated; deterministic fallback when infrastructure degrades
  • Fail-closed policy matrix — service-to-service automation denied in production; only a named human approver can authorise
  • Verified end to end — a 14-event synthetic burst drove OPEN → HYPOTHESIS_READY → AWAITING_APPROVAL → REMEDIATING in 0.8 min on a 7.9 GB laptop

Applied AI & ML

lessongen — Self-Evaluating Lesson Generator

Agentic AI

An agentic generate → evaluate → regenerate loop that writes a lesson, judges it against a hard pass/fail rubric, and regenerates until it clears the bar — shipping the verified lesson together with a full rejection-log audit trail.

  • 13 checkpoints, no partial credit — deterministic (textstat, wordfreq, parse) and LLM-judge hybrid
  • Self-evolving memory — append-only JSONL event log; thresholds adapt within hard caps and are never removed
  • Audit the judge — a golden-set harness measures stability and ground-truth agreement; an unstable judge fails CI
  • Cost and provenance — token usage, USD estimate and git sha recorded per run
  • Model-agnostic — LiteLLM across OpenAI, Anthropic and Ollama; a deterministic stub runs offline with no API key
